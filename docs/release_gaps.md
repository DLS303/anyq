# Разрывы релиза Anyq

Дата проверки: 19 октября 2026. Контур: `apps/web` (Next.js 15, ru/kk) и `apps/api` (FastAPI, `store.py`, `data/db.json`). Flutter (`apps/mobile`) в релиз не входит.

Это аудит. Код приложения не менялся.

## Как проверялось

- Локально подняты API `127.0.0.1:8010` и web `127.0.0.1:3000`. Web запущен с пустым `NEXT_PUBLIC_PILOT_MODE` (полный интерфейс).
- Вход выполнен формой под ролями: владелец, подрядчик, технадзор, поставщик, покупатель, модератор, администратор, специалист (архитектор). Гость просмотрен без входа.
- Отдельной роли «водитель» в коде нет. Прораб, снабжение и заказчик на объекте — это роли участника объекта, а не отдельные учётные записи.
- Пилотный режим (`NEXT_PUBLIC_PILOT_MODE=1`) сверен по `apps/web/src/middleware.ts`, `apps/web/src/components/site/ProjectHub.tsx` и `.env.example`. Второй процесс Next.js в тот же `.next` ломает сборку, поэтому пилот в браузере повторно не поднимался.
- Эндпоинты вызваны напрямую, время замерено. Чтения уложились в единицы миллисекунд. Загрузка фото дневного отчёта: 260 мс (800×600) и 622 мс (4000×3000). Эндпоинтов медленнее 1 с в этом прогоне не было. Зависаний запроса не поймано.

Статусы:

- **WORKS** — сценарий проходит от экрана до сохранённых данных.
- **PARTIAL** — основной путь живой, но не хватает проверки, пустого состояния, языка или части данных.
- **STUB-MOCK** — кнопка или вкладка есть, действия нет либо стоит ручная замена внешней системы.
- **BROKEN** — ожидаемый путь для обычного пользователя ломается.
- **DEMO-ONLY** — иллюстрация или генератор. В релизе такой экран должен жить за отдельным демо-режимом.

## Что проходит от экрана до API

Проверено в этом прогоне и подтверждено кодом:

- Вход с согласием на ПД, `/v1/auth/me`, журнал согласий.
- Список и карточка материалов, отказ заказа ниже минимальной партии.
- Смена статуса заказа материала поставщиком. Покупатель получает 403.
- Создание сделки и перенос по этапу. Неизвестный этап отклоняется.
- Отметка счёта оплаченным только получателем. Чужой пользователь получает «Отметить оплату может только получатель».
- Чтение и отправка сообщения в своём чате. Чужой чат — 403.
- Дневной отчёт подрядчика. Покупатель без доступа к объекту получает 403.
- Дефект, фото дневного отчёта, публичная ссылка на отчёт.
- Утверждение изменения бюджета технадзором. Подрядчик получает отказ.
- Назначение участника объекта по email существующего пользователя.
- Создание объекта владельцем. Подрядчик создать объект не может.
- Расчёт автосметы и ставка НДС 16% на дату 2026-10-19. Поле ранее подписанных актов равно 0.
- Очередь модерации участков отвечает модератору по API. Экран `/ru/moderation` при этом уводит на главную.

## P0 — без этого релиз показывать нельзя

Оценки — ориентир на одну правку в текущем коде, без миграции всей платформы.

### P0-1. Рабочая база при пустом файле заполняется вымышленными данными

**Что не так.** Если `data/db.json` нет или коллекция пустая, `MemoryStore` записывает участки, специалистов, материалы, CRM, чаты и объект «ИЖС Бесагаш». Пароль демо-аккаунтов в `ANYQ_ENV=production` не ставится, но сами записи сида всё равно попадают в файл.

**Файлы.** `apps/api/app/store.py` (`_load`, `_ensure_seed_users`, `_ensure_materials`, `_ensure_site`, `_ensure_crm`), `apps/api/app/seed.py`, `apps/api/app/seed_phase2.py`, `apps/api/app/seed_materials.py`, `apps/api/app/seed_crm.py`, `apps/api/app/seed_site.py`.

**Что сделать.** В production не вызывать сид. Демо-набор включать только отдельным флагом демо-режима. Релиз стартует с пустыми коллекциями и живыми учётными записями.

**Оценка.** 8 ч.

**Пересечение.** Деплой: от этого зависит, чем заполняется база при первом старте.

### P0-2. Иллюстрации стоят в основной навигации

**Что не так.** В полном интерфейсе пользователь открывает вкладки, которые не отражают данные объекта.

- Шахматка рисует корпуса и цены генератором. Вкладка подписана как иллюстрация. API шахматке нет. `apps/web/src/components/crm/CrmChessView.tsx`, `apps/web/src/components/crm/CrmBoard.tsx`.
- Чертежи: комментарий в `apps/web/src/components/site/PdfDrawingViewer.tsx` описывает синтетический PDF. Поле `drawing.file` не читается. Загрузить чертёж объекта через API нельзя (`POST /v1/site/projects/{id}/drawings` → 404).
- 3D-модель коттеджа собирается в браузере, размеры на макете фиксированные. `apps/web/src/components/site/Bim3dViewer.tsx`.
- КС-2/КС-3 печатаются в браузере. Подпись остаётся в памяти `SignaturePad`. Ранее подписанные акты API всегда отдаёт нулём (`apps/api/app/store.py`, `prior_signed_acts`). Ставка НДС при этом живая: `apps/api/app/routers/acts.py`, `apps/api/app/tax.py`.

**Что сделать.** Убрать эти вкладки из релизной навигации и оставить их за отдельным демо-флагом. Если КС и чертежи нужны в релизе, сохранять документ и файл на сервере и считать ранее подписанное из сохранённых актов.

**Оценка.** Спрятать за флаг: 8 ч. Сохранение КС и подписей: ещё 16 ч. Загрузка настоящих чертежей: 12 ч.

**Пересечение.** Стабильность web: тяжёлые клиентские пакеты `three`, `pdfjs`, `jspdf` уже в `apps/web/next.config.ts`. Закупки эту вкладку не заменяют.

### P0-3. На экране висят признаки проверки, которых нет

**Что не так.** Карточка каждого материала показывает «Сертифицировано в РК» без поля в данных. `apps/web/src/components/materials/MaterialView.tsx`. Карточка специалиста показывает «Лицензия II подтверждена», если в записи `license_verified=true`. В сиде флаг выставлен вручную, запроса в реестр лицензий нет. `apps/web/src/components/specialists/SpecialistProfile.tsx`, `apps/api/app/seed_phase2.py`. Модуль gov-gateway помечен stub.

**Что сделать.** Убрать бейджи, пока нет источника проверки. После появления источника показывать статус только по ответу этой проверки.

**Оценка.** 6 ч.

**Пересечение.** Нет.

### P0-4. Тексты согласий — незаполненный шаблон, казахская страница отдаёт русский текст

**Что не так.** `apps/web/content/legal/privacy.ru.md`, `pd-consent.ru.md`, `ai-consent.ru.md` содержат пропуски вида «___» и `https://__________`. Файлов `*.kk.md` нет. `/kk/legal/privacy` показывает казахский заголовок и русский текст шаблона. Согласие при входе ссылается на эти документы.

**Файлы.** `apps/web/src/app/[locale]/legal/[doc]/page.tsx`, `apps/api/app/legal.py`.

**Что сделать.** Заполнить реквизиты и утверждённую редакцию. Добавить казахский текст и отдавать его на `/kk`.

**Оценка.** 12 ч, из них основной объём — тексты, не вёрстка.

**Пересечение.** Нет. Ветка согласий уже хранит версию документа. Менять модель согласия не требуется.

### P0-5. Технадзор, специалист, модератор и владелец не создаются регистрацией

**Что не так.** `store.register` принимает только `buyer`, `contractor`, `supplier` и требует компанию и БИН. Остальные роли появляются только из сида. В релизе без сида технадзор и автор надзора некого назначить в команду объекта.

**Файлы.** `apps/api/app/store.py` (`register`), `apps/api/app/routers/auth.py`, `apps/web/src/components/login/LoginView.tsx`.

**Что сделать.** Приглашение в компанию и на объект для ролей supervisor и specialist. Админа и модератора заводить отдельной операцией, не публичной формой.

**Оценка.** 16 ч.

**Пересечение.** Нет.

### P0-6. Данные живут в одном JSON-файле

**Что не так.** `DATABASE_URL` читается в настройки и в ответ `/health` (`database: false` при пустой переменной), запросы идут в `data/db.json`. Каждая запись переписывает файл целиком под блокировкой. Два процесса API будут затирать друг друга. Идемпотентность хранится в памяти процесса и через 8 секунд ожидания отвечает конфликтом (`apps/api/app/idempotency.py`).

**Файлы.** `apps/api/app/store.py`, `apps/api/app/config.py`, `apps/api/app/routers/health.py`, `docker-compose.yml`, `infra/postgres/init.sql`.

**Что сделать.** Подключить уже описанную схему Postgres в том контуре, который готовит деплой. До этого релиз держать на одном процессе и не обещать горизонтальное масштабирование.

**Оценка.** 40 ч на проводку хранилища. Делать в задаче деплоя, не параллельным вторым диффом.

**Пересечение.** Деплой. Этот пункт не дублировать отдельной миграцией в других ветках.

### P0-7. Пример окружения включает пилот с пустой вкладкой закупок

**Что не так.** `.env.example` задаёт `NEXT_PUBLIC_PILOT_MODE=1`. В пилоте меню уже, а на объекте есть вкладка «Закупки». Она рендерит пустой текст «Здесь появится сравнение цен поставщиков» и ссылку на автосмету. `apps/web/src/components/site/ProjectHub.tsx`. `GET /v1/site/projects/{id}/procurement` отвечает 404. В полном интерфейсе этой вкладки нет, зато скрыты и рабочие земляные экраны: middleware прячет `/catalog`, `/plots`, `/publish`, `/compare`, `/moderation` при любом значении флага.

**Что сделать.** До появления закупок не показывать вкладку как рабочий раздел. Флаг пилота в примере для релиза выставить так, как решено для поставки. Земляной контур либо явно выключить в навигации и модулях (сейчас `modules.py` уже пишет, что рынок земли отключён), либо перестать редиректить его при выключенном пилоте.

**Оценка.** 4 ч на флаги и пустые состояния. Сам модуль закупок сюда не входит.

**Пересечение.** Закупки. Вкладку и модели `procurement` / `submittals` не переписывать в этой задаче: их делает соседняя ветка.

### P1-6. Контакты и часть сделок сида не сходятся с пользователями

**Что не так.** Владелец видит 0 контактов, администратор — 6: у сидовых контактов пустой `owner_id`, а доступ есть только у staff. Сделка материалов ссылается на `supplier_id="u-supplier"`, пользователь поставщика имеет id `u-supply`.

**Файлы.** `apps/api/app/seed_crm.py`, `apps/api/app/seed_materials.py`, `apps/api/app/store.py` (`can_access_contact`).

**Что сделать.** Вместе с отключением сида в production поправить ссылки, если демо-набор останется для демо-режима.

**Оценка.** 3 ч.

**Пересечение.** Деплой и P0-1.

### P1-7. Автосмета выглядит как нормативная, оставаясь коэффициентной

**Что не так.** Экран показывает «Дата базы 09.2026», регионы и НДС 16%. Расчёт идёт по ставкам в `apps/api/app/estimate.py`. Ответ API предупреждает, что это не локальная смета по ЭСН/СН РК. Пресеты `/v1/estimates/presets` web не вызывает. Кнопка «Посчитать демо-дом» сидит на том же экране.

**Что сделать.** Оставить расчёт как предварительный бюджет и назвать его так на ru и kk. Кнопку демо-дома убрать из релиза.

**Оценка.** 4 ч.

**Пересечение.** Нет.

### P1-8. Роль модератора в текущем контуре без экрана

**Что не так.** Очередь `/v1/moderation/queue` для модератора возвращает участки. Страница `/ru/moderation` уходит на главную. В меню модерации нет.

**Файлы.** `apps/web/src/middleware.ts`, `apps/web/src/components/moderation/ModerationView.tsx`.

**Что сделать.** Если земля вне релиза, не создавать модераторов земли и не оставлять роль без задачи. Если земля в релизе, открыть очередь при выключенном пилоте.

**Оценка.** 4 ч.

**Пересечение.** Нет, пока закупки не используют ту же роль.

### P1-9. Риск долгих запросов на фото и на повторе идемпотентного ключа

**Что не так.** В прогоне порог 1 с не превышен. Обработка фото дневного отчёта синхронно гоняет OpenCV в запросе (`apps/api/app/media.py`). Повтор того же ключа идемпотентности ждёт до 8 с. Запись JSON блокирует процесс на время всего файла.

**Что сделать.** Вынести разбор фото из запроса или ограничить размер до лёгкого пути. Не ставить несколько worker-процессов на один файл.

**Оценка.** 8 ч.

**Пересечение.** Стабильность web и деплой.

### P1-10. Заявки с земли и избранное есть в API и не показаны

**Что не так.** Клиент умеет `fetchInquiries`, `fetchFavorites`, `fetchSavedSearches`, `fetchMyPlots`, `fetchModules`. Экраны кабинета их не вызывают. Сравнение участков копит id и не ведёт на `/compare`. Эти маршруты всё равно закрыты middleware.

**Файлы.** `apps/web/src/lib/api.ts`, `apps/web/src/components/plots/PlotCard.tsx`, `apps/web/src/components/cabinet/CabinetView.tsx`.

**Что сделать.** В релизе без земли удалить пункты из меню и не обещать их в текстах. Либо открыть маршруты и довести кабинет.

**Оценка.** 6 ч на скрытие, 16 ч на возврат земли в кабинет.

**Пересечение.** Нет.

### P1-11. Трансграничное согласие можно записать только через API

**Что не так.** `POST /v1/auth/consents/cross-border` есть. В `ConsentsPanel` тип отображается, отдельной кнопки выдачи нет.

**Оценка.** 4 ч.

**Пересечение.** Нет. Модель согласий на этой ветке уже есть.
