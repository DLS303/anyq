# Резервные копии

`deploy/backup.sh` снимает одну копию за запуск. `deploy/anyq-backup.cron` вызывает его каждый час, в 10-ю минуту, часовой пояс `Asia/Qyzylorda`.

## Состав

- База `anyq`: `pg_dump -Fc`.
- Том `anyq-data`: архив загрузок и медиа.

Оба файла шифруются `age`. На сервере лежит только публичный ключ, переменная `AGE_RECIPIENT`. Приватный ключ в репозиторий не попадает. Для снятия копии он не нужен. Его держат офлайн и приносят только на время восстановления.

`rclone` копирует зашифрованные файлы на два remote. Имена remote задаются в `deploy/.env`: `RCLONE_REMOTE_1` и `RCLONE_REMOTE_2`. Оба хранилища находятся в Казахстане. Адреса и ключи доступа настраиваются на сервере командой `rclone config` от пользователя `deploy` и в репозиторий не записываются. В `deploy/.env.production.example` вместо имён стоят пустые значения и `<set-on-server>`.

Срок хранения локально и на обоих remote — `BACKUP_RETENTION_DAYS`, по умолчанию 14 дней.

Перед каждой миграцией сервис `db-backup` по-прежнему пишет локальный `pg_dump -Fc` в том `anyq-backups` и оставляет три последних файла. Этот снимок не шифруется и с сервера не уходит.

## Ключ

На машине, которая не обслуживает приложение:

```bash
age-keygen -o <путь вне репозитория>
age-keygen -y <тот же путь>
```

Вывод второй команды записывают в `AGE_RECIPIENT`. Файл ключа на сервер не копируют. Для `deploy/restore.sh` путь к нему передают в `AGE_IDENTITY_FILE`. После проверки файл с этой машины удаляют.

## Восстановление

Скрипт создаёт отдельную базу и не пишет в рабочую `anyq`:

```bash
deploy/restore.sh --remote <имя remote> --scratch-db anyq_restore
```

Порядок внутри скрипта: `rclone copy`, `age -d`, `pg_restore`. Если база с таким именем уже есть, скрипт останавливается и ничего не удаляет.

Конкретный снимок:

```bash
deploy/restore.sh --remote <имя remote> --stamp YYYYmmddTHHMMSSZ --scratch-db anyq_restore
```

Архив загрузок имеет тот же штамп: `anyq-data-<штамп>.tar.gz.age`. Его расшифровывают `age -d` и распаковывают в пустой каталог. Рабочий том скрипт не перезаписывает.

Проверка круга на синтетической строке и одноразовом ключе:

```bash
bash scripts/ci/backup_roundtrip.sh
```

Нужны `age`, `rclone` и серверные бинарники PostgreSQL 16. Если на машине отвечает Docker, тот же скрипт дополнительно проходит путь через compose. Дамп в артефакты CI не выкладывается.

## Вне этого изменения

Непрерывный журнал WAL и pgBackRest сюда не входят. Образ базы в `deploy/docker-compose.prod.yml` остаётся `postgres:16-alpine`. Строка локали ICU для нового кластера записана в `deploy/postgres-icu-locale`; её читает проверочный контейнер CI.
